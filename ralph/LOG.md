## S13 逢人配 + 炸系层级修正 done
- 依据：维基引《江苏省掼蛋竞赛简易规则 2017 版》原文——
  「红心花色的级牌…可以充当任意牌点的花色牌（即除大小王）搭配使用，称为"逢人配"」；
  同花顺「可以压五张及以下的炸弹，但六张及以上的炸弹比同花顺更大」；
  「A 在三连对、二连三、顺子、同花顺中可作为 1，最小者，也可作为 K+1」。
  规则与实现写进 docs/superpowers/specs/2026-10-22-wild-card.md。
- 逢人配：本局级数的**红桃**级牌是万能牌。identify 里枚举它替代成 2..A 识别牌型
  （花色沿用自身，同花顺另走「补同花色那张」特例），多解时取牌型强的、同型取点数大的；
  legalMoves 额外生成它能凑的牌型（成组、补顺子一格、三带二/连对、钢板）；
  交出去的是原牌，扣牌按原 id。
- 顺手修了两条一直错的规则：
  ① 原来「同花顺压一切炸弹」——官方是同花顺只压五张及以下的炸弹，六张及以上反过来压它；
  ② A 在连对/钢板里也能当 1（最小）或 K+1（最大），原来只认顺子里的 A 可高可低。
- UI：红桃级牌标「配」角标（黑底），其余级牌「级」角标（琥珀底）；
  AI 给逢人配牌值 +30（它比普通级牌灵活），不轻易甩掉。
- 已知简化：手里两张万能配时只按同点替代枚举（成对子/三张/炸弹），
  两张万能配分占顺子两格暂不支持。

### 补记：CI 红了——本地验的命令和 CI 不是一条
- 这轮推上去 CI 的 `bun run test` 挂了，本地却全绿。原因：**CI 用 `bun run test`
  （vitest 跑在 Bun 上），我本地一直用 `bunx vitest run`（vitest 跑在 Node 上）**。
  Bun 的 CompressionStream 实现和 Node 不一样，`void writer.write()` + `void close()`
  在 Bun 上会截断 gzip（Z_BUF_ERROR "unexpected end of file"）。
- 修法（src/core/replay.ts）：
  ① 先 `await writer.write()` 再 `await writer.close()`（不等写完就 close 会截断）；
  ② 但**只写不读会顶住背压**，write 的 promise 永不 resolve（浏览器会卡死）——
     所以先 `new Response(stream.readable).arrayBuffer()` 开始读，再写、再关；
  ③ 解压流报错时要提前挂 catch，否则会变成「未处理的 rejection」，Bun 下直接判失败。
- 顺带把测试超时写进 vite.config.ts（testTimeout 180s）：400 局自动对局回归要跑十几秒，
  CI 机器更慢，别让机器慢变成测试红。
- **教训记下来：以后本地验收一律用 `bun run test`（和 CI 同一条命令）。**

## S26 复盘链接紧凑编码 done

## S35 玩法说明校对（说明单里的规则要跟实现一致） done
- 这轮不看尺寸、只读**文案**——把玩法说明逐条跟实现对了一遍，发现五处对不上：
  - 「头游那队升 1 级；对家（双下）升 3 级」**漏了 1+3 升 2 级**这一档；
  - 「天炸（同花色的 4 张同点）」**说错了**——天炸是大小王共四张，
    同花四张根本不是天炸（写成这样会把人教错）；
  - 「顺子（5 张以上）」——实现只认正好 5 张，写「以上」会让人以为 6 张也能出；
  - 「进贡后新一局的头游照旧领出」**跟实现相反**——进贡局是**进贡的下游**先出牌，
    都抗贡才由头游领出；
  - 「级牌在顺子里当相邻点数用」——实现是按级牌**原来的点数**算；
  - 顺带把「炸弹（4 张同点）」补成「4 张及以上同点」。
- 说明单是玩家学规则的第一入口，写错比不写更糟——这几条都会直接教错人。
