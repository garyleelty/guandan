# 官方规则口径对齐（V1.7）：接风 · 进贡 · 还贡 · 抗贡

**日期:** 2026-10-23
**父项目:** 掼蛋网页版（见 `2026-10-18-guandan-webgame-design.md`）
**依据:** 《淮安掼蛋竞赛规则》口径，经南京信息工程大学 / 东南大学掼蛋比赛规则 PDF、
北京日报「专家教一手」、中文维基百科「掼蛋」条目互证（2026-10 检索）
**状态:** 已落地（引擎 + AI + UI + 联机序列化 + 测试）

## 为什么要改

四条规则与官方现行口径有偏差，其中「接风」实现的是**早期口径**（维基明确标注
现行规则已改为对家接风），进贡/还贡/抗贡是 tribute-design（V1.5）当时
「逢人配还没做」留下的口子——逢人配上线后没有回头补。

## 采纳的规则（官方现行口径）

1. **接风（对家借风）**：一家打出最后一手牌且其余各家都不压时，
   下一圈由他的**搭档**领出（不是顺时针下家）。搭档已打空的情形在打完前
   必然构成双下整场结束，所以引擎里搭档兜底顺延只是防御性代码。
2. **进贡必须交最大的一张**，且**红桃级牌（逢人配）不能进贡**——
   手里最大的是逢人配时，交剩下最大的那张（同点多张任交一张）。
3. **还贡不能还级牌**：还牌仍是「点数不大于 10」，但级牌（含逢人配）
   不能还。手里一张可还的都没有时不设限（沿用防卡死兜底）。
4. **抗贡 = 进贡方合计两张大王**：单下即进贡者一人手里两张大王；
   双下时两名进贡者手里的大王**加在一起**算（天王炸含两张大王自然满足）。
   一大一小两张王**不能**抗贡（旧实现算可抗贡，已改）。
   抗贡是任一进贡者的声明动作：一人声明**全队免贡**，已交的贡牌退回，
   由头游领出（与旧口径一致）。

## 引擎改动（src/core/engine.ts）

- `doPass` 收招胜者打空：领出权给搭档 `((winner + 2) % 4)`，不再顺延下家。
- `canAntiTribute(hands: Card[][])`：**签名变了**——从单手牌改为手牌数组
  （进贡方全体合计）。调用点：`doGive`、`ai.ts`、UI（Table/TributePanel）。
- 新增 `tributeCandidates(hand, level)`：进贡可交的牌（最大牌、排除逢人配）。
- 新增 `returnCandidates(hand, level)`：还贡可还的牌（≤10 且非级牌；
  一张都没有时返回整手牌 = 兜底不设限）。`doGive` 的还贡分支改用它。
- `doGive` 抗贡分支：校验进贡方合计；声明后把**已交**的贡牌退回手牌、
  全部 givers 标记抗贡，直接进 `startTributeReturns`（payers 空 → 头游领出）。

## UI 与联机

- `TributePanel` / `Table`：交贡/还贡的可选牌用 candidates 限制（不可选的变暗）；
  抗贡按钮按「进贡方合计」判定。
- **客人看不到别人手牌**，抗贡可用性由房主算好随状态广播：
  `serializeFor` 在 `tribute` 上附加 `antiOk: boolean`（仅 `step === 'give'` 有意义）。
  UI 侧统一 `tribute.antiOk ?? 本地计算`——单机/房主走本地，客人走广播值。
- AI（`ai.ts`）：抗贡判断改合计口径；交贡用 `tributeCandidates`；
  还贡用 `returnCandidates` 取最小。

## 测试口径备注（写给以后改测试的人）

- **进贡局的级数 = 上一局头游那队升级后的级数**（`newTributeRound` 读
  `prev.levels`，而 `maybeEnd` 已经升过级）。造进贡测试时先算清 delta：
  例如「0 头游、1 二游、2 三游、3 四游」是 1+3 → even 队 +2 → 级牌是 4。
- 测试里选贡牌要用 `tributeCandidates(...)[0]`，不要写 `hand[0]`——
  手牌是按**开局时**的级数排的，升级后级牌的实际位置会变。
- 抗贡路径概率极低（进贡方合计两张大王），soak 覆盖为 0 属正常，单测已覆盖。
